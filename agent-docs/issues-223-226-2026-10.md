# Incidencias 223–226 y reanudación de flashcards

Revisión iniciada el 14 de octubre de 2026 sobre `80c772ae`, rama
`integration/crosspoint-2026-10-07`. Release `1.6.5.2` publicada el 15 de
octubre de 2026, con autorización del usuario. Sin instalación en hardware.

## Diagnóstico y alcance

| Reporte | Evidencia y actuación |
| --- | --- |
| [#223: X al avanzar un EPUB](https://github.com/franssjz/cpr-vcodex/issues/223) | La X corresponde al fallo de preparación de un capítulo. Se corrige una causa demostrable de rechazo prematuro: el control de memoria abortaba antes de intentar la recuperación de cachés que ya usa el asignador. Ahora libera cachés recuperables antes de descartar CSS o abortar, como máximo una vez por bloque de entrada. Conserva el CSS cuando recupera suficiente memoria; no modifica umbrales, formatos de caché ni el fallback existente. Sin el EPUB, los ajustes y el registro del usuario no se puede atribuir a esta causa todo el reporte de 1.6.0.38. |
| [#224: OTA en X3 bloqueado](https://github.com/franssjz/cpr-vcodex/issues/224) | Es una consulta de compatibilidad; no contiene un fallo concreto. El código selecciona la partición inactiva real y valida tamaño, digest, chip y placa antes de activarla. Las pruebas simuladas cubren ambos slots X3/X4, pero no validan un X3 bloqueado. No se modifica OTA. |
| [#225: despertar en la carpeta](https://github.com/franssjz/cpr-vcodex/issues/225) | En el arranque sin splash, `ReaderActivity::onEnter()` encolaba el lector real; antes de aplicarlo, `ActivityManager::loop()` ejecutaba el dispatcher saliente y sustituía el destino por su carpeta. Ahora aplica las transiciones pendientes sin ejecutar entradas de la actividad saliente. También permite completar una transición a suspensión cuando existe una liberación de botón suprimida. |
| [#226: SD SanDisk de 32 GB](https://github.com/franssjz/cpr-vcodex/issues/226) | La comparación local con CrossInk encuentra el mismo controlador SD, SdFat 2.3.1, frecuencia X4 de 40 MHz y parches relevantes. FAT32 y exFAT ya están soportados. Sin logs de montaje ni la versión exacta de CrossInk no se identifica un arreglo seguro. No se modifican SDK, frecuencia, formato ni datos de la tarjeta. |
| Reanudar flashcards tras dormir | Se guardan las respuestas al suspender o abandonar mediante Home. Una instantánea acotada conserva tarjeta actual, cara, desplazamiento, cola pendiente y contadores. El despertar verificado consume su destino antes de abrirla; Back, recuperación y rutas de reinicio conservan prioridad. |

La comparación SD usa CrossInk local `9914146e` con SDK `6993701`, frente al
SDK `9729236` de CPR. No identifica la versión de CrossInk usada por el autor
de #226, que sigue sin especificarse.

La instantánea de flashcards ocupa como máximo 1.248 bytes para los 600 índices
permitidos. Se comprueban versión, tamaño, integridad, límites, memoria y una
huella del mazo, progreso y ajustes. Si el archivo está dañado o ya no corresponde
al mazo, se inicia una sesión nueva con las respuestas persistidas. Un error de
guardado no se anuncia como sesión recuperable. El escritor de progreso conserva
el archivo anterior ante documentos incompletos, escrituras parciales o fallo al
cerrar; esto no garantiza atomicidad ante cualquier fallo físico de la SD.

## Validación automatizada

- Pruebas nativas del parser con memoria normal, fragmentación recuperable,
  agotamiento irrecuperable y presión repetida entre bloques. Verifican texto
  completo y CSS conservado.
- Transiciones reales de `ActivityManager` con dobles de hardware: arranque,
  push/pop, callbacks, guardas de botones, suspensión desde menús y exclusión USB.
- Instantáneas: ida/vuelta, repetición del sueño, truncamiento, corrupción,
  cambio de mazo/ajustes/progreso, límites y errores de almacenamiento.
- `test/simulator/sleep_resume.py` usa libros y tarjetas sintéticos y SD
  desechables. Comprueba suspensión manual y por inactividad, reejecución del
  proceso y conservación visual del contenido. El simulador usa un adaptador
  nativo de criptografía; no valida TLS, OTA ni libros protegidos.

Resultados: **664/664 pruebas nativas correctas**, incluidos los ocho casos de
ciclo de actividades y los ocho de persistencia de flashcards. Contra el código
anterior fallan cinco de los ocho casos de actividades, incluido el arranque sin
splash que acababa en la carpeta; con la corrección pasan todos.

**6/6 escenarios del simulador correctos, 12 arranques:** EPUB, TXT y flashcards,
cada uno con suspensión manual y con timeout real de un minuto. Se comparan los
píxeles antes/después, se comprueba el archivo de Quick Resume durante el sueño
y su consumo al despertar, y se verifica que una respuesta correcta de
flashcards permanece guardada exactamente una vez. Se inspeccionaron las
capturas de lectura y tarjeta reanudadas. Las fuentes del simulador coinciden
con las finales salvo las dos inclusiones explícitas del backend criptográfico
nativo en la copia aislada. No se modifica el SDK del repositorio.

## Publicación de la release — 15 de octubre de 2026

Se publica el tag [1.6.5.2-cpr-vcodex](https://github.com/franssjz/cpr-vcodex/releases/tag/1.6.5.2-cpr-vcodex)
sobre `03ff5c94`, con las notas en inglés de `CHANGELOG.md`. Incluyen la corrección de reanudación del lector, la
persistencia de las sesiones y respuestas de flashcards, y la recuperación de
memoria del parser. La mitigación de #223 no se presenta como confirmación
definitiva del reporte; #224 y #226 continúan pendientes de evidencia física.

El [CI del commit](https://github.com/franssjz/cpr-vcodex/actions/runs/38646175039)
supera tests, formato, cppcheck y compilaciones default/X4 Pro. La segunda es
solo interna. El [workflow de release](https://github.com/franssjz/cpr-vcodex/actions/runs/38647034908)
repite las regresiones nativas y publica únicamente los cuatro assets C3:
BIN, metadatos JSON y los dos informes de presupuesto. No se publica X4 Pro.

El BIN oficial generado por GitHub Actions mide **6.277.600 bytes**, con
**276.000 bytes libres** en el slot X4. RAM estática: **61.944 bytes**.
Pasa el presupuesto original del 97,5 %. Su SHA-256 es
`e812f64bdf08d0c657ed1a40ad427749b2fc4033db12791244f4c239586bb8ec`.
Este es el artefacto publicado; la tabla anterior describe las compilaciones locales.

README, enlaces y Auto Flash se sincronizan mediante

## Comprobación física pendiente

1. En X4/X3, abrir un libro, avanzar, dormir y despertar varias veces, tanto
   manualmente como con Quick Resume tras inactividad. Repetir desde recientes
   y desde un menú del lector; comprobar página, ajuste y orientación.
2. En flashcards, responder, voltear una tarjeta, dormir y despertar; comprobar
   tarjeta/cara y resumen final, sin duplicar respuestas o sesiones.
3. Para #223, repetir una lectura prolongada con el EPUB y los ajustes afectados.
   Registrar el fallo de capítulo y el heap si reaparece la X.
4. Para #226, conservar ambas SD y obtener el log del primer montaje fallido,
   incluida la línea `[SD] SD card not detected (err=..., data=...)`, versión de
   CrossInk que funciona y si el fallo ocurre en arranque frío o al despertar.
5. #224 requiere una prueba real del modelo y firmware instalado, con su ruta
   de recuperación ya conocida. No se infiere recuperabilidad USB por el modelo.

No se cambian particiones, bootloader, eFuses ni rutas de actualización. La
distribución de X4 Pro continúa retirada. No se cierran las incidencias en
GitHub basándose solo en estas pruebas.
